Keep the cache. Invalidate it on the write.

A cached read that shows old data after a write in another module is not a reason to delete @SkipIfCached or CACHE_NO_TIMEOUT. The cache stays. The write emits a change signal. The facade that owns the slot calls store.invalidateCacheFor. Specs cover the cached hit and the refetch.

Wrong fix, then the idiom

Wrong

Stale list after a create in another module. The agent deletes the decorator or shortens the TTL so the next read always hits the network.

@SkipIfCached('LIST', store, true, CACHE_NO_TIMEOUT)
load() { /* fetch */ }

Right

The writer does not touch the other module's store. A root-level signal carries the change. The facade invalidates that key.

changes.notify('LIST')
store.invalidateCacheFor('LIST')

Cross-module refresh

Write

Create succeeds in the other module.

→

Signal

Root service emits the cache key. No store import across the module boundary.

→

Refetch

Facade calls invalidateCacheFor. The next read misses the cache and loads the fresh value.

Enforcement ladder

1. Rule and skills

Path-scoped rule for TypeScript and C#. Not always-on. OpenCode keeps the same text off the startup instructions and points coder and tdd-guide at it.

  • rules/common/cache-invalidation.md
  • instructions/cache-invalidation.md
  • flurryx, angular-cop, store and test patterns
  • .NET: evict or tag-invalidate

2. Review, Important

code-reviewer and angular-cop BLOCK. dotnet-cop BLOCK for IMemoryCache, HybridCache, and output cache.

  • Cache removed or bypassed, no invalidation
  • Write beside a cached read, no refresh-after-write test

3. Diff hook, warn-only

cache-invalidation.sh on the branch diff. Exit 0. Cursor preToolUse allows the tool and shows the rule. Stop does not block.

  • Net removal of @SkipIfCached, CACHE_NO_TIMEOUT, or another cache marker
  • Quiet when the diff adds invalidateCacheFor or onCacheInvalidate

Why the hook warns and does not block

Content checks in stop.sh warn. ship-stop-gate blocks only an unfinished autonomous goal. A real deletion of a cache must stay possible, and a comment-only or generated diff can look like a removal. Blocking the stop would loop the agent. The hook cannot see a new write next to an untouched cache; that case stays on the Important review.
