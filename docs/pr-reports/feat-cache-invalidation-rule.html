Invalidate on the write. Remove a cache only when told.

A cached read that shows old data after a write is not a reason for the agent to delete @SkipIfCached, CACHE_NO_TIMEOUT, or a TTL. The cache stays. The write emits a change signal. The facade that owns the slot calls store.invalidateCacheFor. Specs cover the cached hit and the refetch. A removal is allowed only when the task, spec, or PR description explicitly says so, and the change names the knock-on effects.

Who decides to remove the cache

Agent's own fix

Stale list after a create in another module. The agent deletes the decorator or shortens the TTL so the next read always hits the network. That is Important. Invalidate from the write instead.

@SkipIfCached('LIST', store, true, CACHE_NO_TIMEOUT)
load() { /* fetch */ }

Explicit instruction

The task, spec, or PR description says to remove the cache. The removal is allowed. It is a note, not Important. Name callers that still expect the cached value, and tests that only cover the hit.

task: remove @SkipIfCached on load()
note: callers lose the cached hit

Cross-module refresh

Write

Create succeeds in the other module.

→

Signal

Root service emits the cache key. No store import across the module boundary.

→

Refetch

Facade calls invalidateCacheFor. The next read misses the cache and loads the fresh value.

Enforcement ladder

1. Rule and skills

Path-scoped rule for TypeScript and C#. Removal or bypass is allowed only on an explicit instruction. An instructed removal still names knock-on effects.

  • rules/common/cache-invalidation.md
  • instructions/cache-invalidation.md
  • flurryx, angular-cop, store and test patterns
  • .NET: evict or tag-invalidate

2. Review

code-reviewer, angular-cop, and dotnet-cop. Only an uninstructed removal or bypass is Important. An instructed removal is a note.

  • Uninstructed removal, no invalidation — Important
  • Write beside a cached read, no refresh test — Important, unchanged

3. Diff hook, warn-only

cache-invalidation.sh still exits 0. The message says the removal is fine if it was explicitly instructed. Otherwise invalidate on the write.

  • Net removal of @SkipIfCached, CACHE_NO_TIMEOUT, or another cache marker
  • Quiet when the diff adds invalidateCacheFor or onCacheInvalidate

Why the hook warns and does not block

Content checks in stop.sh warn. ship-stop-gate blocks only an unfinished autonomous goal. The hook cannot read the task, so it cannot tell an instructed removal from an agent's own fix. It warns either way and still allows the tool. Blocking the stop would loop the agent on a removal the task asked for. A new write next to an untouched cache stays on the Important review.
