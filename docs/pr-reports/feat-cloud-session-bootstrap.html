settings-opencode 0.4.28 · feat/cloud-session-bootstrap

A remote Claude session installs Monolith. A local one stays quiet.

SessionStart runs cloud-session-bootstrap.sh first. The hook clones the settings repo and runs install.sh --yes monolith only when the host is remote and the project does not already vendor the harness. Every other path exits 0 before git runs. A clone or install failure logs a warning and still exits 0.

What SessionStart decides

1 · Gate

Remote only

CLAUDE_CODE_REMOTE must be the string true. Unset, false, or any other value is a no-op.

→

2 · Vendored?

Project already has it

A .harness-variant stamp, CLAUDE.md plus autonomy-context.sh, or a plugin.json with a version field skips the clone.

→

3 · Install

Shallow clone

Clone fmflurry/settings-opencode at depth 1 into a temp dir, then install.sh --yes monolith. Output is discarded.

→

4 · Session

Never fail start

Missing git, a failed clone, or a failed install prints one warning on stderr and exits 0. The temp dir is removed.

ConditionResult

Vendored .claude harness or plugin version markerno-op
Only .claude/settings.json, no harness filesstill installs

Default variant

No name given

Monolith

./install.sh --yes, settings-sync, bootstrap.ps1, and the interactive prompt all install Monolith. HARNESS_VARIANT still wins when it is already set.

Name it

Conductor

conductor or --variant conductor still selects Conductor. orchestration remains an alias. The source checkout stays the Conductor tree.

Wired in two places. The installer merges bash ~/.claude/hooks/cloud-session-bootstrap.sh as the first SessionStart command. The Cursor plugin build mirrors the same script onto sessionStart.
