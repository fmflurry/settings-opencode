One feature, from the local KPI log

agent-harness kpi feature reads ~/.agent-harness/kpi/events.jsonl for this repo and branch. The PR number joins the key once an event carries it, or when --pr is passed. Conductor and Monolith both run this before the show-me HTML. pr-report then inserts the Metrics panel below.

1. Log Same JSONL

Skill, agent, tool_result duration and ok, tokens. No prompts or absolute paths.

▶
2. Feature repo + branch

Wall time is first event to last. Active time drops gaps longer than 5 minutes.

▶
3. File .metrics.json

Sanitised aggregates committed at docs/pr-reports/<slug>.metrics.json so the VM log is not required later.

▶
4. PR Panel and table

pr-report adds this panel and a ## Metrics table. The check warns if they are missing. It does not fail.

What the report counts

FieldSource
SessionsDistinct session per host: cursor, claude, opencode
Tools and skillstool_call only. A tool_result is not a second call
Agentsmain versus each subagent. A Task call on the parent stays on main
Failurestool_result with ok: false, plus duration when the host sent one
TokensSum of session end and subagent stop. n/a when unknown
Kept out Nothing the log already refuses
  • Prompts, tool arguments, and absolute paths
  • Session ids (only the count per host)
  • Events from another repo or branch

An empty match is partial. Unknown tokens are not.
