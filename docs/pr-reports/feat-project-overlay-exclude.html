Project overlay survives a re-vendor

./install.sh --local still vendors Conductor or Monolith (Monolith when no variant is named). After that copy, .harness-local/ wins, listed skills stay gone, and the domain-rules hook stays off until the project turns it on.

1. Vendor Harness copy

Skills, hooks, AGENTS.md, .cursor, and .agents land in the project. The installer never writes .harness-local/.

▶
2. Exclude Prune listed paths

angular-ddd and skills/dotnet-ddd are deleted from .claude/skills, .opencode/skills, and .agents/skills.

▶
3. Overlay Project files win

.harness-local/.claude/skills/ddd and AGENTS.md are copied on top. A path in both exclude and the overlay stays.

▶
4. Hook Off by default

Claude and OpenCode call domain-rules. The project script runs only when "enabled": true.

exclude One entry per line
  • angular-ddd or skills/angular-ddd removes that skill from all three skill trees.
  • AGENTS.md or a path under .claude, .opencode, .cursor, or .agents is deleted.
  • A bad line deletes nothing and the installer exits 2.

Paths are compared after symlink resolution, so a harness clone under macOS /tmp still applies the overlay. A skipped root prints the reason. A local install records ./.claude/mods/autonomy-status and, for Monolith, .opencode/instructions/monolith.md.
